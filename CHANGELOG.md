## [v0.1.0] - 2026-11-01

### Highlights

- A registry of credentials without their values: what each is for, how and where it is made, what it may do, where it is stored, who uses it and how it rotates, in Go or JSON, validated by one set of rules and described by generated JSON Schemas
- An event log that turns into each credential's work progress and next step (`to-create`, `to-record`, `to-deploy`, `deployed`) and its lifecycle state (`ok`, `due`, `overdue`, `expiring`, `expired` and more)
- Reports for people: a self-contained HTML report with filters, a management plan with the launch checklist and rotation calendar, an iCalendar export and a Markdown reference, plus a `status` gate for deploy scripts

### Added

- `credspec` package: the `Credential` entry with its issuer, generation, entitlements, stores, consumers, rotation, revocation and exposure; well-known kinds, issuers and store types as open slugs, and closed sets for status, sensitivity, method, store role and rotation policy; `Registry.Validate` reports every problem with its entry's ID ([`a699f14`](https://github.com/plexusone/systemspec-credential/commit/a699f14))
- Event log with `created`, `rotated`, `expires`, `deployed`, `verified` and `revoked` events, kept sorted and validated against the registry; `Assess` gives each credential's lifecycle state, reason and next date within a warning window ([`3d0beca`](https://github.com/plexusone/systemspec-credential/commit/3d0beca))
- `schema` package: registry and event log JSON Schemas generated from the Go types with their documentation comments, and embedded; JSON files refuse unknown fields ([`d463d4e`](https://github.com/plexusone/systemspec-credential/commit/d463d4e))
- `report` package: JSON report rows, a self-contained HTML report with search, filters, sorting, details, shareable URL state and CSV download, and a time-independent Markdown reference ([`dcf9f73`](https://github.com/plexusone/systemspec-credential/commit/dcf9f73))
- `cli` package and `credspec` command: `validate`, `status`, `report`, `record`, `export` and `schema`, mountable over a registry built in Go with `cli.New` ([`cfb4460`](https://github.com/plexusone/systemspec-credential/commit/cfb4460))
- `handling`: whether a person or a system generates, distributes and rotates each credential, with the counts by stage and the rotations a person does each year in every report ([`8bef956`](https://github.com/plexusone/systemspec-credential/commit/8bef956))
- `reaches` and `dependsOn` with `Exposes` and `ExposedBy`, so each credential shows what its leak exposes and what exposes it; per-store `install` steps and consoles; `account` entries with `protections` and `recovery`; a by-place checklist of what a person creates ([`60b0e6b`](https://github.com/plexusone/systemspec-credential/commit/60b0e6b))
- Management plan in Markdown (summary, launch checklist in dependency order, rotation calendar, account protections, exposure) and an RFC 5545 calendar of rotations and expiries with reminders and stable event IDs ([`c348309`](https://github.com/plexusone/systemspec-credential/commit/c348309))
- `--environment-order` and `--system-order` set the order of the plan's launch checklist ([`e878b62`](https://github.com/plexusone/systemspec-credential/commit/e878b62))
- Work progress from `created`, `rotated` and `deployed` events, with each credential's next step in every report; `status --progress` and `--manual`; `record` accepts `*` patterns ([`d242e08`](https://github.com/plexusone/systemspec-credential/commit/d242e08))
- `to-record` progress separates credentials that exist but have nothing recorded from those still to create; the HTML report's work chips, including one for what a person creates, count within the other filters ([`f8eedd6`](https://github.com/plexusone/systemspec-credential/commit/f8eedd6))
- Reports carry their as-of date, read back by `report.AsOf`, so a committed copy can be rebuilt and compared
